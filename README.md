## Documentation approach

I try to write documentation from the user's point of view rather than from the implementation outward. That means reproducing the workflow, validating assumptions, documenting failure states, and giving readers examples they can actually follow.

Areas I especially enjoy:

- installation, deployment, and configuration workflows
- APIs, SDKs, and integrations
- troubleshooting and failure states
- docs-as-code and version-controlled documentation
- technical tutorials grounded in working examples

I also write about software engineering, Linux, AI tooling, developer experience, and the process behind the things I build on **[DEV Community](https://dev.to/mikachu)**.
